# Documentation Map

`docs/` contains two different classes of material.

## Canonical documentation

```text
docs/foundation/
→ durable product, architecture, data, collaboration, and operations contracts

docs/knowledge/
→ current routing, ownership, implementation map, proof boundary, decisions
```

These are development authorities together with current source.

## Reference / design material

Existing directories such as:

```text
docs/MIVUBI-UI-UX-Redesign/
docs/building/
```

contain screenshots, generated mockups, prompts, pixel references, and building/reference artifacts.

They are evidence/reference only unless a current user instruction or Foundation decision explicitly promotes a specific requirement.

Do not infer current product mechanics, accepted UI behavior, palette counts, dimensions, or implementation obligations merely from whichever reference file is easiest to open.

## Owner rule

One current responsibility should have one canonical owner. Git history owns ordinary historical versions; do not create parallel current `_old`, `_new`, backup, or `v2` documentation without a real external requirement.
